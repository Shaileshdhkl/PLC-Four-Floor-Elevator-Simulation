# PLC-Based Four-Floor Elevator Control Simulation

An educational controls engineering project by Shailesh Dhakal, an Electrical Engineering student at the University of South Florida.

Developed in Rockwell Automation Connected Components Workbench using ladder logic and the Allen-Bradley Micro850 simulator.

## Project Overview

The controller stores requests for four floors, selects destinations based on retained travel direction, and coordinates travel with door opening, dwell, and closing. An active destination remains locked during travel; additional requests are stored for later service.

## My Contribution

- Developed state-based ladder logic for request capture, destination selection, travel, and door sequencing.
- Implemented door/motion interlocks, position checks, fault-code diagnostics, and a travel watchdog.
- Implemented latched faults and conditional reset requiring a fresh Start command after fault recovery.
- Diagnosed premature watchdog timeouts during valid travel, changed the preset from 30 to 60 seconds, and repeated normal and blocked-travel tests.
- Executed and documented 23 functional simulation checks.

## Operating Sequence

Idle -> Upward/Downward Travel -> Door Opening -> Door Dwell -> Door Closing -> Idle

A normal Stop pauses operation while retaining the active trip. A fault disables operation, clears stored requests, and enters the latched fault state. Clearing a fault does not automatically restart operation.

| Code | Condition |
| --- | --- |
| 1 | Simulated emergency-stop input |
| 2 | Invalid position |
| 3 | Travel watchdog timeout |

## Testing and Troubleshooting

The project report records 23 functional checks covering initialization, upward/downward travel, stored and additional requests, door sequencing, Stop/resume behavior, injected faults, blocked reset, and deliberate restart. All listed checks passed after the documented corrections. Several checks were performed within the same run; this is not a quantified reliability test or independent certification.

## Simulation Scope and Limitations

- Position and door feedback are generated by ladder logic, not physical sensors.
- The project does not include a physical elevator, commissioned I/O, or a completed HMI.
- Emergency-stop behavior is a scanned software response, not a safety-rated hardware function.
- Exact response-time measurements, exhaustive fault combinations, and hardware commissioning are outside the completed scope.
- This educational project is not suitable for controlling a passenger elevator.
